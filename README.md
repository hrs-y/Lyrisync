# Lyrisync

<img src="design/logo.svg" width="96" alt="Lyrisync 圖示" />

[下載最新版](https://github.com/hrs-y/Lyrisync/releases/latest)・[發佈網頁](https://hrs-y.github.io/Lyrisync/)・MIT 授權

為 Spotify 補齊缺少的歌詞，並提供 Apple Music 式顯示效果的 Windows 桌面程式（Tauri 2 + TypeScript）。

目前進度：**完整播放頁＋桌面歌詞**。已完成以下功能：

- **播放頁**：專輯封面、歌名、歌手、進度條、播放控制，可以全螢幕。
- **背景**：從封面取色、緩慢流動的多彩背景。
- **歌詞**：逐字同步，多來源搜尋並快取；有「亮起」和「書寫」兩種效果。
- **歌詞後處理**：簡繁轉換、翻譯、日文歌的羅馬拼音。
- **桌面歌詞**：透明、永遠在最上層的兩行歌詞，可以鎖定讓滑鼠穿透。
- **設定**：動畫品質、歌詞效果、字級、字體、粗體與景深模糊、桌面歌詞等。
- **介面語言**：繁體中文、English、日本語。
- **連結 Spotify（選用）**：精準比對、預先載入下一首、待播清單、按讚。

## 開發

需要 Node.js、Rust（MSVC 工具鏈）和 Visual Studio Build Tools。

```bash
npm install
npm run tauri dev   # 啟動桌面程式，讀取正在播放的 Spotify
npm run dev         # 只開前端，在瀏覽器裡用模擬播放器、示範歌詞和示範封面預覽畫面
npm test            # 單元測試
npm run typecheck   # 型別檢查
```

**快速開啟**：桌面和開始功能表有「Lyrisync 開發版」捷徑，執行的是 `scripts/open-app.ps1`（和安裝版的「Lyrisync」捷徑分開）。
- 已經開著：把視窗叫到前面。
- 還沒開：用開發模式啟動（`npm run tauri dev`），所以跑的永遠是最新的程式碼。
- 工作列會多一個縮到最小的命令列視窗，裡面看得到進度；關掉 app 時一起結束。啟動失敗時它會停住，讓你看錯誤訊息。
- Rust 有改動時，第一次啟動要先編譯，會等比較久。


## 畫面

- **左右分欄**（有歌詞時）：
  - 左邊是封面、歌名與歌手、進度條、播放控制。封面在暫停時會縮小。
  - 點封面或專輯名稱在 Spotify 開啟專輯，點歌手開啟歌手頁（多位歌手各自可以點）。對應到 Spotify 的歌時直接用 ID 開，否則用名稱在 Spotify 裡搜尋；沒裝桌面版 Spotify 時改開網頁版。
  - 右邊是逐字歌詞；最後一行之後是歌詞來源，有多個版本時附「其他版本」。
  - 歌詞欄右上角是「譯」「羅」、「重新搜尋」和待播清單圓形按鈕；待播清單在最右邊，打開時其他按鈕隱藏，它不會移動。
- **封面置中**（找不到歌詞、純音樂時）：封面放大移到中央，下方附「重新搜尋」。
- **窄視窗**：上方小封面加歌名，中間歌詞，下方控制列。
- **大小**：以封面邊長為基準，封面跟著視窗的高與寬一起縮放；歌詞欄寬度、歌詞字級、歌名和按鈕都跟著它。最大化時整組內容變大並置中，兩旁不會空出一大片。
- **背景**：從封面取出幾種主要顏色，各佔一塊邊緣柔和的區域，用 WebGL 緩慢移動、旋轉，交界像液體一樣捲動。
  - 封面主色的區域最大；只有單一色系的封面會往色相兩側延伸出相鄰的顏色，深淺也拉開。偏灰的封面維持低彩度。
  - 不會出現封面上的圖案；換歌時顏色平順地漸變。
  - 依背景亮度自動加深暗色遮罩，白字一直看得清楚。
- **無邊框視窗**：標題列空白處可以拖曳，雙擊可最大化；右上角是桌面歌詞、全螢幕、設定和視窗按鈕。
- **全螢幕**：滑鼠停 2.5 秒後，標題列、歌詞工具列和游標淡出。視窗是最大化時會先還原再進全螢幕，避免下方留下工作列高度的黑色一條；離開後恢復最大化。

## 歌詞效果

設定頁的「歌詞效果」可以選：

- **亮起**（預設）：整段歌詞先顯示，唱到的字由左往右亮起、緩緩上浮。
- **書寫**：還沒唱到的行看不到，唱到的字才由左往右一個一個寫出來。
  - 剛寫下的字從微微模糊、稍低的位置落定，像墨跡剛寫上去。
  - 目前這一行寫在畫面中間，上面是已經寫好的行。翻譯和羅馬拼音也跟著寫出來。
  - 只有逐行時間的歌詞，依字數估計每個字的時間。
  - 手動捲動時，還沒唱到的行會淡淡地顯示，方便找到想跳去的行。

桌面歌詞的效果在設定頁的「桌面歌詞」分開選，例如主畫面用亮起、桌面歌詞用書寫：

- **亮起**（預設）：唱到的字填上封面的顏色；第二行沒有羅馬拼音、翻譯時預告下一句。
- **書寫**：唱到的字才一個一個寫出來，羅馬拼音、翻譯也跟著寫；不預告下一句。
  - 第一句開唱前先顯示歌名和歌手。
  - 換行時寫好的上一行往上飄、淡出，新的一行從空白開始寫。

## 外觀

設定頁「歌詞 → 外觀」：

- **粗體**：關掉時每種字體改用較細的字重（例如明體 600 → 400、Yu Gothic 700 → 500）；桌面歌詞也一樣。
- **景深模糊**：離目前這一行越遠越模糊，可以關掉；**模糊程度**可在 40%～200% 之間調整。只有動畫品質為「高」時才會模糊。
- **其他行亮度**：目前這一行以外的歌詞亮度，12%～70%（預設 30%）。

## 介面語言

設定頁「一般 → 語言」用卡片選「跟隨系統」、繁體中文、English、日本語（每張卡用該語言自己的寫法，下面附目前介面語言的名稱）。

- 跟隨系統時：系統語言是中文（不分繁簡）用繁體中文，日文用日文，其他用英文。
- 換語言時主視窗和桌面歌詞會重新載入一下。
- 介面文字在 `src/i18n/`：`zh-TW.ts` 是基準，`en.ts`、`ja.ts` 少一個鍵型別檢查就會擋。
- 日文介面優先用日文字型（Yu Gothic），假名和漢字才不會用中文字形。歌詞每一行都標上自己的語言，不受介面語言影響。
- 歌詞來源附的翻譯都是中文，所以英文、日文介面不顯示翻譯，也沒有「譯」按鈕、翻譯開關和 T 快捷鍵（羅馬拼音照常）。
- 除錯面板與事件紀錄是開發工具，維持中文。

## 歌詞字體

設定頁「歌詞 → 字體」裡，中文、日文、英文各選一種，主畫面和桌面歌詞都會套用：

| 語言 | 選項 |
|---|---|
| 中文 | 黑體（預設，微軟正黑體）、明體（思源宋體）、文楷（霞鶩文楷）、標楷（標楷體） |
| 日文 | ゴシック（預設，Yu Gothic）、明朝（Shippori Mincho）、教科書體（Klee One）、丸ゴシック（Zen Maru Gothic） |
| 英文 | Sans（預設，Segoe UI）、Garamond（EB Garamond）、Baskerville（Libre Baskerville）、Playfair（Playfair Display） |

- **每一行的語言**：有假名是日文、有漢字是中文，只有拉丁字母的行用英文字體。日文歌裡只有漢字的行也用日文字體。
- **英文字體排在最前面**：中日文歌詞裡夾雜的英文字也用選的英文字體。
- **字重**：每種字體用最好看的字重（例如明體 600、標楷體沒有粗體就用原本的字重），不會被硬加粗。Garamond 的小寫字母比較矮，英文行放大 1.1 倍。
- **打包**：除了 Windows 內建的黑體、ゴシック、Sans、標楷，其他都是開源字型（SIL OFL），打包在程式裡，選到時才載入；中日文字型拆成上百個小檔，只會載入歌詞用到的字。授權見 `THIRD_PARTY_NOTICES.md`。

## 動畫品質

設定頁可以選「自動／高／中／低」。

| 等級 | 背景 | 歌詞 |
|---|---|---|
| 高 | 流動背景 60fps | 彈簧物理捲動、下方各行錯落跟上、遠近模糊、長音發光、逐字母浮起 |
| 中 | 流動背景 30fps | 彈簧物理捲動、錯落、長音發光（不做模糊和逐字母動畫） |
| 低 | 靜態色塊 | 整塊捲動，不做發光與浮起 |

選「自動」時，起始等級和降級規則如下：

- **系統要求減少動態效果**：用「低」。
- **無法使用 WebGL**：用「中」。
- **其他情況**：用「高」。
- **自動降級**：每 4 秒算一次平均影格時間，畫面不夠順就降一級，而且只降不升。

## 連結 Spotify（選用）

不連結也能正常使用：播放狀態一律從 SMTC 讀，時間最準。連結 Spotify Web API 之後多四個功能：

- **精準比對**：換歌時向 Spotify 查這首歌的歌曲 ID 和 ISRC，直接查 AMLL TTML DB 的 Spotify 資料夾（2026 年 10 月約收錄 2,300 個 Spotify 歌曲 ID 的手工逐字歌詞），不必靠歌名猜。這個 ID 沒收錄時，再用 ISRC 查索引找同一個錄音的其他 ID。用這個方式找到的歌詞，來源說明會寫「依 Spotify 歌曲 ID 對應」。
- **預先找下一首**：目前這首找完歌詞後，讀播放佇列，先幫接下來兩首找好；換歌時歌詞立刻出現（就算 SMTC 和 API 的歌手寫法不同，也會用歌名、專輯和長度認出來）。
- **待播清單**：歌詞欄右上角的清單按鈕（Q）把右欄換成接下來要播的歌（小封面、歌名、歌手、長度），預先找好歌詞的標上「歌詞已備妥」。開著時每 30 秒更新一次；只能預覽，不能點歌。
- **按讚**：播放頁歌名右邊的愛心，加入或移出「已按讚的歌曲」。視窗回到前景時會重新查一次（可能在 Spotify 裡改過）。
- 封面、歌手連結不連結也能用（改用搜尋）；連結後直接用 ID 開到正確的專輯與歌手。

### 設定方式

1. 打開 [Spotify 開發者後台](https://developer.spotify.com/dashboard)（設定頁有按鈕），用自己的 Spotify 帳號登入。
2. 按「Create app」：名稱、說明隨意；API 勾選 **Web API**；**Redirect URI** 填 `http://127.0.0.1:47823/callback` 後按「Add」（一定要用 127.0.0.1，Spotify 不接受 localhost）；同意條款後儲存。
3. App 的「Settings → User Management」：把自己的名字和 Spotify 帳號的 Email 加進去。開發模式最多 5 個帳號，只有名單裡的能用。
4. 「Settings → Basic Information」複製 **Client ID**，貼到本程式「設定 → Spotify」，按「連結」，在瀏覽器裡同意授權。**不需要 Client Secret。**

### 注意事項

- Spotify 規定開發者 App 的擁有者要有 Premium；授權每半年過期一次，到時設定頁會顯示「需要重新連結」，按一下就好。
- 只要求四個權限：讀目前播放的歌與播放佇列、讀取與修改「已按讚的歌曲」。不控制播放（播放控制照樣走 SMTC）。
- 登入用 PKCE，refresh token 存在 Windows 認證管理員，access token 只放在記憶體；前端只能呼叫幾個固定的端點。
- 連結前存的歌詞快取沒用歌曲 ID 查過，連結後每首歌會重新搜尋一次。
- Spotify 沒有公開的歌詞 API；非官方的抓法要用帳號 cookie，也違反開發者條款，所以沒有做。

## 歌詞來源

所有來源同時查詢。精細度優先（逐字 > 逐行 > 純文字），同一級再依來源排序。

| 來源 | 精細度 | 說明 |
|---|---|---|
| AMLL TTML DB | 逐字 | 社群手工對時，品質最好，附背景人聲與對唱標記。用網易雲的歌曲 ID 查；連結 Spotify 時也用 Spotify 的歌曲 ID 與 ISRC 查。鏡像站和 GitHub 同時詢問 |
| QQ 音樂 | 逐字（QRC）／逐行 | 華語歌多，附翻譯；日文歌常附逐字的羅馬拼音。歌詞有加密，解密方式改寫自 jixunmoe-go/qrc（MIT） |
| 網易雲音樂 | 逐字（YRC）／逐行 | 華語、日韓歌多，附中文翻譯與羅馬拼音 |
| LRCLIB | 逐行 | 社群資料庫，西洋歌多 |
| 酷狗 | 逐字（KRC） | 西洋歌、周杰倫的歌也有逐字版本，附翻譯。搜尋要用簡體字 |

比對與處理規則：

- **比對**：歌名、歌手、長度都要對得上。
  - 歌手不同的候選一律不採用，避免抓到翻唱版。
  - Spotify 用英文名稱、來源用原文（例如日文）的歌手，長度差在 1.5 秒內才採用。
  - 逐字歌詞要求長度差在 3 秒內。
- **羅馬拼音**：顯示的版本沒有羅馬拼音時，向其他找到的版本借用（對方要有一半以上的行附羅馬拼音）。
- **顯示時機**：AMLL 的逐字歌詞一拿到就顯示，其他結果最多等 1.2 秒，看有沒有更好的版本。
- **快取**：
  - 結果存進程式的快取資料夾，找到的保留 30 天，找不到的 3 天後重試。
  - 有來源連線失敗時不寫快取。
- **簡繁轉換**：網易雲、酷狗的簡體歌詞會轉成繁體，只轉字形、不換用語。日文歌的歌詞不轉，但翻譯會轉。
- **過濾**：開頭的「作詞：」等製作人員資訊、「歌手 - 歌名」標題行會被去掉。

歌詞的著作權屬於原作者。本程式只在使用者自己的電腦上即時抓取並快取，不架設伺服器、不散布歌詞，僅供個人使用。

## 架構

### Rust（`src-tauri/src/`）

- `smtc.rs`：
  - 背景執行緒每 100ms 讀一次 SMTC，有變化才送出 `player://snapshot` 事件給前端。
  - 換歌後分 5 次重讀封面圖，因為 Spotify 的封面常比歌名晚更新，封面真的換了才更新封面編號。前端用 `smtc_artwork` 取得封面的二進位資料。
  - 跳轉、播放／暫停、上一首／下一首等指令也從這裡送出。
- `net.rs`：代前端連線，避開 CORS。只允許 HTTPS 和白名單裡的主機，伺服器忙碌（503／429）時自動重試。
- `cache.rs`：歌詞快取的讀寫與清除，每首歌一個 JSON 檔。
- `desktop.rs`：開關桌面歌詞視窗（透明、無邊框、永遠在最上層、不顯示在工作列）。
- `spotify.rs`：Spotify 的 PKCE 登入（暫時在 127.0.0.1:47823 接收回呼）、權杖保存與自動更新、API 代理（只允許固定幾個端點，遇到 429 依 Retry-After 暫停）、在 Spotify 開啟專輯與歌手（只接受 22 碼 ID 或編碼過的搜尋字串）。錯誤一律回傳代碼，由前端翻譯。

### 前端（`src/`）

- `player/`：
  - **播放時鐘**：用偶爾回報的進度推算目前播到哪裡。換歌或跳轉後的緩衝期直接對準，不做平滑。
  - **換歌判定**：進度歸零但歌名還沒變時，先觀望再決定。
- `lyrics/`：
  - 各格式解析器：LRC、YRC、KRC、QRC、TTML。
  - 比對、排名、簡繁轉換、製作人員過濾。
  - 搜尋服務與快取；`providers/` 是各歌詞來源。搜尋時可以帶入這首歌在 Spotify 上的資料，也可以預先搜尋播放佇列裡的歌。
- `spotify/`：Spotify Web API 的呼叫與解析（`api.ts`），換歌時對應曲目、讀播放佇列、按讚（`session.ts`），錯誤代碼轉成文字（`errors.ts`）。
- `i18n/`：介面文字（繁體中文、英文、日文）、依系統語言選擇、`data-i18n` 屬性翻譯 HTML。
- `ui/queueView.ts`：待播清單。
- `ui/lyricView.ts`：歌詞畫面。
  - **逐字填色**：每個字的演唱進度寫進 CSS 變數 `--p`，由遮罩從左往右填亮。
  - **上浮**：另外寫進 `--lift`，用緩起緩停的曲線、至少花 0.65 秒。亮著那一行的每個字各自放到 GPU 圖層，可以停在小數像素，不會一格一格地跳；唱完後落回原位。
  - **長音**：一道平滑的波從第一個字母走到最後一個（`--bump`）。
  - **捲動**：每一行有自己的彈簧，換行時下面的行錯開出發。
  - **模糊**：依距離寫入 `--blur`。
  - **間奏點點**：間奏超過 4 秒時，三個點依進度亮起並呼吸。
  - **書寫效果**：還沒唱到的行隱藏；字的墨跡進度寫進 `--ink`。只有逐行時間的行用 `ui/writing.ts` 依字數估計每個字的時間。
- `ui/playerView.ts`：封面、歌名、進度條與播放控制。切換版面時用 FLIP 動畫平滑移動。
- `ui/color.ts`：封面取色（OKLab 分群、單一色系延伸相鄰色相）與遮罩濃度。
- `ui/background.ts`：WebGL 流動背景，以及低品質用的靜態色塊。
- `desktop/`：桌面歌詞視窗。自己讀 SMTC 對時，歌詞由主視窗送來；鎖定時定時查游標位置，游標在解鎖按鈕上才關掉滑鼠穿透。
  - `karaoke.ts` 是亮起效果的卡拉 OK 填色，`writingLine.ts` 是書寫效果（每個字的遮罩 `--p` 與墨跡落定 `--ink`）。
- `ui/quality.ts`：各品質等級的效果開關，以及「自動」模式的掉幀偵測。
- `ui/fonts.ts`：歌詞字體清單、判斷每一行的語言、寫入 `--lyric-family-*` 等 CSS 變數並載入打包的字型。
- `ui/settingsPanel.ts`、`settings.ts`：設定頁（分類、分段選擇器、開關、滑桿）與設定儲存。
- `ui/titlebar.ts`、`ui/debugPanel.ts`：標題列、除錯面板。
- `styles/`：依區塊分開的樣式。字型、顏色、圓角、動態曲線、圖層順序統一定義在 `base.css`。

## 已量測的 Spotify 行為

- **進度回報**：播放中約每 4.5 秒更新一次 SMTC 的進度，用最後更新時間推算的誤差在 ±2ms 內。
- **跳轉**：Spotify 接受 SMTC 的跳轉指令。跳轉或換歌後會緩衝 100～230ms。
- **換歌順序**：
  - 手動換歌時，歌名和進度歸零會同時到。
  - 自然播完、自動換下一首時，進度和長度會先歸零，約 0.1 秒後歌名才換，所以需要觀望。
